Two file icon themes for Phantom's explorer. **Symbols** is the full set: 354 icons covering almost every file type and folder you will meet, and the theme Phantom's explorer is designed against. **Symbols Starter** is eight icons and a sixty-line manifest, kept here as a template to copy. Neither installs a program, starts a process or asks for approval.

Anything a theme does not match falls through to Phantom's SF Symbols table, so a small theme is usable rather than half broken.

## The icons

<IconBrowser theme="symbols" title="Symbols" height="tall" />

Search matches the icon's name and every key that points at it, so `tsx`, `yarn.lock` and `node_modules` each find the icon that draws them. The categories come from the theme file itself: an icon a folder map names is a folder icon, one a file name or a suffix names is a file icon, one only a language id reaches is a language icon, and one nothing Phantom reads names is unused.

## Getting started

<Steps>
  <Step title="Install the extension">
    In Phantom, open the Extensions pane in the sidebar (or Settings → Extensions) and press **Install** next to Symbols Icons.
  </Step>
  <Step title="Open Settings → Sidebar">
    The **File Explorer** section holds the **Icon Theme** picker. The explorer's own gear menu has the same control.
  </Step>
  <Step title="Pick a theme">
    Contributed themes are listed as the theme name followed by the extension that supplied it, so the rows read **Symbols — Symbols Icons** and **Symbols Starter — Symbols Icons**. Every open explorer repaints as you pick.
  </Step>
  <Step title="Go back whenever you want">
    The same picker holds **No Theme (SF Symbols)** for the built-in table on its own.
  </Step>
</Steps>

## What the extension adds

| Theme | Directory | Icons | Default file icon |
|---|---|---|---|
| Symbols | `symbols` | 354, plus a coloured folder set with open, outline and code variants | `document` |
| Symbols Starter | `icon-theme` | 8: JavaScript, TypeScript, JSON, Markdown, lock, image, folder, folder open | none |

Symbols sets `file`, `folder` and `rootFolder`, so every row carries artwork. Symbols Starter sets none of the three, so anything outside its eight keeps the SF Symbol.

## Configuration

<Details summary="The theme file">

Phantom reads the SVG half of the VS Code file icon theme format. A whole theme is one `icon-theme.json` and the SVGs it points at.

```json
{
  "iconDefinitions": {
    "ts": { "iconPath": "./icons/ts.svg" }
  },
  "fileExtensions": { "ts": "ts", "tsx": "ts" },
  "fileNames": { "yarn.lock": "lock" },
  "languageIds": { "typescript": "ts" },
  "folder": "folder",
  "folderExpanded": "folder-open"
}
```

| Key | What it does |
|---|---|
| `iconDefinitions` | Icon id to SVG path, relative to the theme directory |
| `fileExtensions` | Suffix to icon id. A longer suffix wins, so `spec.ts` can differ from `ts` |
| `fileNames` | Whole file name to icon id. A name beats any suffix |
| `languageIds` | Language id to icon id, consulted last |
| `folder`, `folderExpanded` | Icon for a closed and an open folder |
| `file` | Icon for a file nothing else matched |
| `rootFolder`, `rootFolderNames`, `folderNames` | Also read |

Phantom resolves an icon in VS Code's own order: an exact file name first, then the longest matching suffix, then the language id. Keys are matched without regard to case.

</Details>

<Details summary="Making your own">

Settings → Extensions has a **Reveal in Finder** button. Copy either theme directory somewhere of your own, change the SVGs and the mapping, and drop it into Phantom's icon themes folder. Settings → Sidebar names that folder under the Icon Theme picker, and a theme copied there is listed with no install step. Start from `icon-theme`, which is the smaller of the two.

Two rules to keep in mind. A theme is listed under the directory's name unless an extension supplies one, and a contributed theme whose name is already taken by a bundled or copied theme is dropped rather than shown twice. And the icons must be SVG: a theme that draws from a font parses cleanly, draws nothing, and is listed as having no artwork.

</Details>

<Details summary="Adding an icon">

Three lines and a file. Put the SVG in `icons/`, add it to `iconDefinitions` under a new id, and point a suffix or a file name at that id.

```json
"iconDefinitions": { "yaml": { "iconPath": "./icons/yaml.svg" } },
"fileExtensions": { "yaml": "yaml", "yml": "yaml" }
```

Draw at 24 by 24 and keep the artwork inside the box. Raise `version` in `extension.json` afterwards so Phantom sees the change.

</Details>

## Troubleshooting

<Details summary="A theme is not in the picker">

Phantom drops a contributed icon theme whose name is already used by a bundled theme or by one copied into your icon themes folder. Phantom still bundles its own copy of Symbols, listed as `symbols` in lower case, so both rows can appear until the bundled copy is retired. It also needs `icon-theme.json`, or a file whose name ends in `icon-theme.json`, directly inside the directory the manifest names.

</Details>

<Details summary="Some rows still show SF Symbols">

Symbols Starter defines eight icons and no default, so a file type it does not list keeps the symbol Phantom would have drawn. Switch to Symbols for full coverage, or add a `"file"` key naming an icon id.

</Details>

<Details summary="A file has the wrong icon">

Resolution order decides this: a whole file name beats a suffix, and a longer suffix beats a shorter one. `Cargo.lock` matches by name before `.lock` is considered, and a `component.spec.ts` matches a `spec.ts` key ahead of `ts`.

</Details>

<Details summary="The icons look heavy or faint against my theme">

They are flat colour with no outline, chosen to hold up on a light and a dark sidebar. Edit the `fill` and `stroke` values in the SVGs; nothing in Phantom recolours them.

</Details>
