This is a bundle, and it is worth saying so plainly. Nix, CMake and Bruno are three unrelated syntaxes. Nix is a functional language for describing builds, CMake a command language for generating them, Bruno a plain-text format for HTTP requests. They share nothing but the shelf they sit on: files a developer edits beside the code, in a language too small to earn an extension of its own.

They ship together so that three small things cost one install. Nothing here starts a process, so the parts you do not use cost nothing.

None of the three declares a language server. Highlighting is the whole contribution.

## Highlights

<Features>
  <Feature title="Nix" icon="package">
    `let`, `in`, `with`, `rec`, `inherit`, `if`/`then`/`else` and `assert`; attribute names and attribute paths; single and multi-line strings with their `${…}` interpolations; paths and URLs; `#` line and `/* */` block comments. Claims `.nix`.
  </Feature>
  <Feature title="CMake" icon="gear">
    The command names, the flow keywords, `${…}` and `$ENV{…}` variable references, quoted arguments and `#` comments. Claims `.cmake`, and the file name `CMakeLists.txt` whatever its case.
  </Feature>
  <Feature title="Bruno" icon="globe">
    A `.bru` file's blocks — `meta`, the seven request methods, `query`, `headers`, `body` in each of its forms, `vars`, `assert`, `script`, `tests` and `docs` — with the header names and values, and the block bodies coloured in the language they hold. Claims `.bru`.
  </Feature>
  <Feature title="Nothing to install" icon="check">
    All three grammars are data the editor reads. No binary, no `PATH` lookup, no permission prompt.
  </Feature>
</Features>

## Requirements

Nothing to install for Nix or CMake.

Bruno bodies borrow other grammars. A `body:json` block is coloured by the **JSON** extension, `body:xml` by **XML**, a `script` or `tests` block by **TypeScript**, and a `docs` block by **Markdown**. Install the ones your collections use. Without them the block keeps its outline and its content stays plain. A `body:graphql` block has no grammar in this registry and always stays plain.

## Getting started

<Steps>
  <Step title="Install the extension">
    In Phantom, open the Extensions pane in the sidebar (or Settings → Extensions) and press **Install** next to Nix, CMake and Bruno.
  </Step>
  <Step title="Open a file of any of the three types">
    Colour appears at once. Phantom claims none of these itself, so there is nothing to promote.
  </Step>
</Steps>

## What the extension adds

| Area | Contribution |
|---|---|
| File types | `.nix`, `.cmake`, `CMakeLists.txt`, `.bru` |
| Language servers | none |
| Formatters | none |
| Editor | TextMate grammars `source.nix`, `source.cmake` and `source.bru`; `#` comments for Nix and CMake, `//` and `/* */` for Bruno |
| Icons | A separate sidebar icon for each of the three |

## Measured coverage

<Details summary="How much of a real file each grammar colours">

Measured over files the owner wrote, under the scope map Phantom's editor uses. Vendored copies inside a dependency cache are excluded, because they say more about the projects they came from than about this one.

| Language | Files | Non-whitespace characters | Coloured |
|---|---|---|---|
| Nix | 32 | 45,826 | **99.7%** |
| CMake | 4 | 14,248 | **74.6%** |
| Bruno | 16 | 7,494 | **46.2%** |

For scale, the Microsoft TypeScript grammar measures 67% on this repository's own TypeScript sources under the same method.

Nix is as complete as a TextMate grammar gets: attribute names alone account for 36.5% of the file, strings 44.0%, comments 6.5%.

CMake leaves plain what a CMake script is mostly made of — path and target arguments. Of the characters it does give a scope to, 94.3% are painted: comments 36.9% of the file, strings 26.0%, keywords 11.7%. The four files are one large `CMakeLists.txt` and three short example ones, and the short ones score lowest, because a fourteen-line file is almost all arguments.

Two further CMake corpora, measured and then left out of the table: the 37 vendored CMake files in the same checkout score 59.7%, and the 11 `configure_file` templates named `*.cmake.in` score 61.7%.

Bruno's remainder is two things. Block names such as `get` and `headers` are scoped `entity.name.tag`, which Phantom's parity map does not paint, and `docs` blocks are Markdown prose, which it does not paint either.

</Details>

## Troubleshooting

<Details summary="A Bruno body or docs block stays plain">

That block is another language, and its grammar comes from another extension. Install JSON, XML, TypeScript or Markdown, whichever the block holds. A `graphql` body has no grammar here and stays plain in any case.

</Details>

<Details summary="A file named cmakelists.txt in lower case is not recognised">

It is. Phantom lowercases a file name before matching, so `CMakeLists.txt`, `CMAKELISTS.TXT` and `cmakelists.txt` all resolve to CMake.

</Details>

<Details summary="A .cmake.in template stays plain">

The extension claims `.cmake` and the name `CMakeLists.txt`. Phantom matches the last suffix, so `onig-config.cmake.in` is an `.in` file and gets nothing.

The manifest could claim it: `fileNamePatterns` takes globs, and `*.cmake.in` is one entry. It is left out because the 11 such files in the checkout this extension was measured against all sit inside a Zig dependency cache, and none is authored here. The grammar reads them correctly — 61.7% coloured — so ask for the pattern if you write them.

</Details>

<Details summary="Bruno block names are not coloured">

Known, and explained under Measured coverage. The upstream grammar names them with a scope outside the nine kinds Phantom paints. Methods, header values, strings and comments still colour.

</Details>
