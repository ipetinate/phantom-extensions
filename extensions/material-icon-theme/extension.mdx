The Material Icon Theme, packaged for Phantom's explorer. It is [material-extensions/vscode-material-icon-theme](https://github.com/material-extensions/vscode-material-icon-theme) 5.38.1 by Material Extensions, MIT licensed, vendored as the project publishes it: the generated theme map and all 1,251 SVGs, unmodified apart from the path each icon definition points at. Nothing installs a program, starts a process or asks for approval.

It is the widest icon set Phantom can draw. Where **Symbols** names 354 icons, this names 1,252, and it is the folder half that grows most: 4,654 folder names, each with its own open form.

## The icons

<IconBrowser theme="material-icons" title="Material Icon Theme" height="tall" />

Search matches the icon's name and every key that points at it, so `tsx`, `Dockerfile` and `node_modules` each find the icon that draws them. The categories come from the theme file itself: an icon a folder map names is a folder icon, one a file name or a suffix names is a file icon, one only a language id reaches is a language icon, one only the light overrides reach is a variant, and one nothing Phantom reads names is unused.

  </Feature>

## Getting started

<Steps>
  <Step title="Install the extension">
    In Phantom, open the Extensions pane in the sidebar (or Settings → Extensions) and press **Install** next to Material Icon Theme.
  </Step>
  <Step title="Open Settings → Sidebar">
    The **File Explorer** section holds the **Icon Theme** picker. The explorer's own gear menu has the same control.
  </Step>
  <Step title="Pick the theme">
    Contributed themes are listed as the theme name followed by the extension that supplied it. Upstream calls both the same thing, so the row reads **Material Icon Theme — Material Icon Theme**. Every open explorer repaints as you pick.
  </Step>
  <Step title="Go back whenever you want">
    The same picker holds **No Theme (SF Symbols)** for Phantom's built-in table, and every other installed theme beside it.
  </Step>
</Steps>

## What Phantom draws, and what it does not

<Details summary="1,191 of the 1,252 icons can be reached today">

An icon draws when a map Phantom reads names it. 1,191 of the 1,252 definitions are named that way, and 54 of those arrived with Phantom 0.18.0, which reads the map's `light` section and its `rootFolderNamesExpanded` table. The remaining 61 ship as bytes and are named nowhere Phantom looks:

| Icons | Named only by | Why they stay unused |
|---|---|---|
| 1 | `rootFolderExpanded` | `folder-root-open`, the open form of the workspace root. Phantom resolves a root folder before it considers the expanded state |
| 60 | nothing in the file | Icon-pack and alternate variants — the Angular, Nest, Ngrx, Redux and Vuex folder sets, `nodejs_alt`, `php_elephant`, `go_gopher` |

The last group is a property of the published map, not of Phantom. Upstream switches those on through VS Code settings that regenerate the map inside the editor, and the map it publishes is the one its defaults produce. The artwork travels with the package either way, so a future Phantom that reads more of this file finds the files already there.

The 1,252nd definition is not upstream's. It is `solid`, the Solid logo the owner drew, and it is reached by a different road: Phantom asks the project's `package.json` whether it depends on `solid-js` and, in a project that does, draws it on a `.tsx` file that the map alone would have called React. See **A .tsx file does not say who compiles it** below.

</Details>

<Details summary="The light section, and the two keys Phantom still skips">

Phantom 0.18.0 reads the map's `light` section. The sidebar asks the terminal's own background rather than the system appearance, so a light theme inside a dark system is a light sidebar and gets the light artwork.

| Key | What 5.38.1 puts there | What Phantom does |
|---|---|---|
| `light` | 263 overrides for a light background: 31 suffixes, 179 file names, 3 language ids, 25 folder names and their 25 open forms | Read. On a light background the 54 pale twins draw instead of their dark originals |
| `rootFolderNamesExpanded` | empty | Read. Nothing to gain in this version, because `rootFolderNames` is empty too |
| `folderNamesExpanded` | 4,654 | Read, and it is the key that matters most here |
| `highContrast` | `fileExtensions` and `fileNames`, both empty | Skipped. Nothing to lose in this version |
| `rootFolderExpanded` | `folder-root-open` | Skipped. An expanded root keeps `folder-root`, because Phantom resolves a root folder before it considers the expanded state |
| `hidesExplorerArrows` | `false` | Skipped. Phantom draws its own disclosure arrows and a theme does not vote on them. `false` is what it does anyway |

</Details>

<Details summary="A .tsx file does not say who compiles it">

React, Solid, Preact and Qwik all write `.tsx`. One suffix, one grammar, one language server — and a map keyed by suffix has no way to tell them apart, so upstream's `.tsx` entry names React for all of them.

The project does say, in its dependencies. Phantom 0.18.0 reads the nearest `package.json` walking up from the file and, in a project that depends on `solid-js`, draws `solid` on a `.tsx` instead. That icon is the one definition in this package that is not upstream's: the Solid logo the owner drew, added here so the substitution has artwork to reach for.

The same question runs the other way. Both icon packs map eighteen suffixes each — `service.ts`, `component.ts`, `pipe.ts`, `directive.ts`, `guard.ts`, `interceptor.ts`, `module.ts`, `resolver.ts` and their `.js` and `.dart` twins — onto ids like `angular-service`. A NestJS `user.service.ts` wore Angular's shield for exactly that reason. Now a project that does not depend on `@angular/core` does not get Angular's artwork, and the file falls back to what it is: TypeScript.

</Details>

## Configuration

<Details summary="The theme file">

Phantom reads the SVG half of the VS Code file icon theme format. A whole theme is one `icon-theme.json` and the SVGs it points at.

```json
{
  "iconDefinitions": {
    "typescript": { "iconPath": "./icons/typescript.svg" }
  },
  "fileExtensions": { "ts": "typescript" },
  "fileNames": { "tsconfig.json": "tsconfig" },
  "languageIds": { "typescript": "typescript" },
  "folder": "folder",
  "folderExpanded": "folder-open"
}
```

Upstream keeps its map in `dist/` and its SVGs one level above, so every `iconPath` it publishes reads `./../icons/<name>.svg`. Here the map and the `icons/` directory sit side by side, so all 1,251 paths read `./icons/<name>.svg`: the string `"./../icons/` became `"./icons/` 1,251 times.

One definition was added after that, `solid`, pointing at `./icons/solid.png`. Those are the only two edits to the published map, and no other byte of it moved.

Phantom resolves an icon in VS Code's own order: an exact file name first, then the longest matching suffix, then the language id, then the default. A folder resolves by name, by name in its expanded form, and then by the default.

</Details>

<Details summary="Making your own">

Settings → Extensions has a **Reveal in Finder** button. Copy `material-icons` somewhere of your own, change the SVGs and the mapping, and drop it into Phantom's icon themes folder. Settings → Sidebar names that folder under the Icon Theme picker, and a theme copied there is listed with no install step.

A theme is listed under its directory's name unless an extension supplies one. Give a copy a new directory name: a theme whose name is already taken is dropped rather than shown twice.

</Details>

## Troubleshooting

<Details summary="The theme is not in the picker">

Phantom drops a contributed icon theme whose name is already used by a bundled theme or by one copied into your icon themes folder. It also needs `icon-theme.json`, or a file whose name ends in `icon-theme.json`, directly inside the directory the manifest names.

</Details>

<Details summary="A file has the wrong icon">

Resolution order decides this. A whole file name beats a suffix, and a longer suffix beats a shorter one. `component.ts` matches Angular before TypeScript, and `package.json` matches Node by name before `.json` is considered at all.

</Details>

<Details summary="An icon looks too dark on a light sidebar">

The theme carries a light variant for 54 of its icons and Phantom does not read that half of the map yet — see "The five keys Phantom skips". The dark variant draws on both backgrounds until it does.

</Details>

<Details summary="An open workspace root keeps its closed icon">

It does, and it will until Phantom reads `rootFolderExpanded`. Folders inside the root do change artwork when you open them, through `folderNamesExpanded`, which Phantom does read.

</Details>
