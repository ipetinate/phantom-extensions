An environment file is four lines of grammar and a whole class of mistakes. A quote that never closes swallows the rest of the file. A `#` inside a value is a comment or is not, depending on the quoting. A `${OTHER}` is expanded by one loader and left literal by another. Opened as plain text, none of that is visible.

This extension teaches Phantom the syntax: `KEY=value`, the `export` prefix, single and double quoted values, the escapes a double quoted value accepts, `#` comments both on their own line and after a value, `${OTHER}` interpolation, and a quoted value that runs over several lines — which is how a private key or a certificate ends up in a `.env`.

Nothing is installed and nothing is run. No language server exists for this format, and this extension declares none.

## Highlights

<Features>
  <Feature title="Keys and values" icon="check">
    The key, the `=`, and the value told apart. An `export` prefix is coloured as the modifier it is. An empty value is still a valid line, and is treated as one.
  </Feature>
  <Feature title="Quoting that survives a newline" icon="lock">
    A double quoted value that runs to the next line stays a string all the way to its closing quote, so a pasted PEM block reads as one value instead of turning the rest of the file into nonsense. A single quoted value is literal: `${THIS}` inside it is not interpolation, and is not coloured as any.
  </Feature>
  <Feature title="Interpolation and escapes" icon="code">
    `${OTHER}` and `$OTHER` inside an unquoted or double quoted value, and `\n`, `\"` and the rest of the escapes inside a double quoted one.
  </Feature>
  <Feature title="Comments where they really are" icon="book">
    A `#` at the start of a line is a comment. A `#` after whitespace at the end of a value is a comment. A `#` inside quotes is part of the value.
  </Feature>
</Features>

| Area | Contribution |

| Suffix | `.env`, which claims every name ending in it — `dev.env`, `.dev.env`, `production.env` |

## Notes

<Details summary="The two shapes of a variant, and which one is claimed how">

Environment files come in two shapes, and a manifest claims them by two different keys.

**The extension comes last** — `dev.env`, `.dev.env`, `production.env`. A manifest's `extensions` list matches the part after the last dot, so a single entry, `env`, claims every file of this shape, whatever the prefix. Nothing to enumerate and nothing to miss.

**The extension comes first** — `.env.local`, `.env.production`, `.env.development.local`. Here the last dotted segment is `local`, `production` or `local` again. A suffix match cannot see these, and claiming `local` would claim every `settings.local`, `config.local` and `docker-compose.local` in the world. So they go in `fileNames`, one entry per name.

The list is what the tools generate: Next.js, Vite, Create React App, Rails and Ruby's dotenv, Symfony, Laravel, Flask and the dotenv CLI.

```
.env                        .env.production
.env.local                  .env.production.local
.env.example                .env.prod
.env.sample                 .env.prod.local
.env.template               .env.test
.env.defaults               .env.test.local
.env.dist                   .env.testing
.env.schema                 .env.staging
.env.development            .env.staging.local
.env.development.local      .env.stage
.env.dev                    .env.qa
.env.dev.local              .env.ci
.env.vault                  .env.preview
.env.keys                   .flaskenv
```

</Details>

<Details summary="A variant that is not on the list">

The list is an enumeration, so a name nobody standardised is not on it. `.env.dev1`, `.env.eu-west-1`, `.env.blue`, `.env.tenant-acme` — a team that names environments after its own machines, regions or customers has files this extension will not claim, and there is no pattern, glob or prefix a manifest can carry to fix that.

Two things work today. Rename the file to the other shape — `dev1.env` instead of `.env.dev1` — and the `env` suffix claims it with no list involved. Or set the language by hand from Phantom's language menu, which holds for that buffer.

</Details>

<Details summary="What is deliberately not claimed">

`.envrc` belongs to [direnv](https://direnv.net/) and is a shell script, not an environment file. It is executed by bash: it has `if`, `source_up`, `PATH_add` and command substitution in it. The Shell extension colours it correctly, and claiming it here would replace a working shell grammar with one that only knows `KEY=value`.

</Details>

<Callout kind="warning" title="Colour is not concealment">
Highlighting a `.env` makes its secrets easier to read, not harder. Phantom draws what the file holds, the same as any other editor. Keep the real values out of the repository and commit an `.env.example` instead.
</Callout>
