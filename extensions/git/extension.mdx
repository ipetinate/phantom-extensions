Every repository is full of files Git asks a person to write, and until now Phantom opened all of them as plain text. This extension teaches Phantom the six of them that carry a syntax: the ignore list, the config file, the attributes file, the mailmap, the commit message buffer and the interactive rebase todo.

They are six languages, not one, because they share nothing but the `#` comment. An ignore list is a list of globs. A config file is INI with quoted subsections. A commit message is prose above a block of Git's own comments, with a diff underneath when you commit with `-v`. Each one gets its own grammar.

Nothing is installed and nothing is run. Git itself is never invoked: the extension is a set of grammars and file claims.

## Highlights

<Features>
  <Feature title="Ignore lists" icon="search">
    Globs, `**`, `?`, character classes, the `!` negation at the start of a line, escaped `\#` and `\ `, and path separators. The same grammar covers `.dockerignore`, `.npmignore`, `.eslintignore`, `.prettierignore` and `.helmignore`, because those files are the same syntax.
  </Feature>
  <Feature title="Config and attributes" icon="gear">
    `[section]` and `[section "subsection"]` headers told apart, keys, booleans in all six spellings Git accepts, sizes with their `k`, `m` and `g` suffix, paths, and both the `#` and the `;` comment. In `.gitattributes`, the pattern, each attribute, its `=value` and the `-` that unsets it.
  </Feature>
  <Feature title="Commit and rebase buffers" icon="check">
    A subject line over 50 characters is marked, and over 72 marked harder. Git's `#` block below it colours new, modified, renamed and deleted paths differently. Commit with `-v` and the diff at the bottom is coloured as a diff. In the rebase todo, every command from `pick` to `break`, its hash and its message.
  </Feature>
  <Feature title="Mailmap" icon="book">
    The proper name, the addresses in their angle brackets, and the commit name being rewritten.
  </Feature>
</Features>

## Getting started

<Steps>
  <Step title="Install the extension">
    In Phantom, open the Extensions pane in the sidebar (or Settings → Extensions) and press **Install** next to Git.
  </Step>
  <Step title="Open any of the files below">
    There is nothing to configure and nothing to install. A `.gitignore` is coloured the moment the extension is there.
  </Step>
  <Step title="Set Git's editor to Phantom, if you want the commit buffer">
    `git config --global core.editor "phantom --wait"`. Git writes `COMMIT_EDITMSG`, Phantom opens it coloured, and `git commit -v` puts the diff under the message.
  </Step>
</Steps>

## What the extension adds

| Language | File names | Suffixes |
|---|---|---|
| Ignore List | `.gitignore`, `.gitignore_global`, `.dockerignore`, `.npmignore`, `.eslintignore`, `.prettierignore`, `.stylelintignore`, `.helmignore`, `.vercelignore`, `.gcloudignore` | `.gitignore`, `.dockerignore`, `.npmignore`, `.eslintignore`, `.prettierignore`, `.stylelintignore`, `.helmignore`, `.vercelignore`, `.gcloudignore` |
| Git Config | `.gitconfig`, `gitconfig`, `.gitmodules` | `.gitconfig`, `.gitmodules` |
| Git Attributes | `.gitattributes`, `gitattributes` | `.gitattributes` |
| Git Commit Message | `COMMIT_EDITMSG`, `MERGE_MSG`, `SQUASH_MSG`, `TAG_EDITMSG`, `NOTES_EDITMSG` | `.gitcommit` |
| Git Rebase Todo | `git-rebase-todo` | `.gitrebase` |
| Git Mailmap | `.mailmap` | `.mailmap` |

The two columns match differently. A **file name** is the whole name, so `.gitignore` is claimed because it is spelled out. A **suffix** is the part after the last dot of a longer name, so `packages/web/.gitignore` is claimed by the name and `ci.gitignore` by the suffix. The suffixes are there for the files people keep beside a template — `docker.dockerignore`, `deploy.gitignore` — and cost nothing when nobody has one.

Seven grammars ship: one per language, plus `source.diff`, which exists only so the commit grammar can colour the diff a `-v` commit puts below the message.

## Notes

<Details summary="Why the other ignore files are here">

`.dockerignore`, `.npmignore`, `.eslintignore`, `.prettierignore`, `.helmignore` and the rest are not Git files, and they are in this extension anyway. They are the same syntax: a glob per line, `#` for a comment, `!` to bring something back. Docker's builder, npm, ESLint, Prettier and Helm all reimplemented Git's pattern language rather than inventing one.

Splitting them into an "Ignore" extension of their own would ship the same grammar twice and make you install two things to colour two files that read identically. One language, one grammar, every ignore file.

</Details>

<Details summary="Why .pre-commit-config.yaml is not claimed here">

It is YAML. Its last dotted segment is `yaml`, so the YAML extension already claims it, already colours it, and already validates it against a schema through `yaml-language-server`. Claiming it here would take a correctly coloured file and hand it to a grammar that is not YAML.

The `pre-commit` framework is also not Git. It installs a Git hook, which makes it a Git *client*, the way `husky` and `lefthook` are. If its manifest ever deserves more than YAML — key completion, hook id validation — that belongs in a `pre-commit` extension with the schema to back it, not in this one.

</Details>

<Details summary="Files this extension cannot claim">

A `fileNames` entry matches a whole file name with no directory part, so a file that is only identifiable by where it sits cannot be claimed:

| File | Why not |
|---|---|
| `.git/config` | The name is `config`. Claiming it would also claim `~/.ssh/config`, `~/.kube/config` and every unrelated file called `config`. |
| `.git/info/exclude` | The name is `exclude`. Same problem, and the syntax is an ignore list. |
| `.git/info/attributes` | The name is `attributes`. Same problem. |
| `.git/rebase-merge/message` | The name is `message`. Same problem. |
| `~/.config/git/config`, `~/.config/git/ignore` | Git's XDG paths. Both names are too generic to claim. |
| `.git-blame-ignore-revs` | Claimable, but no grammar reads it: it is a list of hashes with `#` comments, and colouring hashes as globs would be worse than plain text. |

Open one of these and it stays plain text. Phantom's language menu can still set the language by hand for that buffer.

</Details>

<Details summary="The Shell dependency">

The manifest depends on `phantom.shell`. The rebase grammar hands the body of an `exec` line to `source.shell`, which the Shell extension provides, and the registry refuses a grammar that reaches into another extension without declaring it.

Installing Git without Shell still colours everything else. The `exec` command keeps the rebase scope instead of shell colours.

</Details>
