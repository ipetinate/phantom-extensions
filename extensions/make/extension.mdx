Make has an awkward syntax and a long memory. A target and a variable assignment are told apart by a colon. There are four assignment operators and they do four different things. A recipe line is shell, but only because it starts with a tab, and a space there is a build error you cannot see. Opened as plain text, a Makefile hides all of it.

This extension teaches Phantom the language: targets and their prerequisites, `=`, `:=`, `?=` and `!=` each coloured as itself, automatic variables, the built-in functions, `ifeq`/`ifdef`/`else`/`endif`, `define` blocks, the special targets such as `.PHONY`, and the `@` and `-` prefixes a recipe line can carry.

Nothing is installed and nothing is run. Make is not invoked, and no language server is declared.

## Highlights

<Features>
  <Feature title="Targets and prerequisites" icon="check">
    The target name, the colon and the prerequisite list are three different things, and pattern rules like `%.o: %.c` keep the `%` apart from the suffix. Order-only prerequisites after the `|` are part of the list. `.PHONY`, `.DEFAULT_GOAL` and the other special targets are recognised by name.
  </Feature>
  <Feature title="Four assignment operators" icon="code">
    `=` recursive, `:=` simple, `?=` conditional and `!=` shell, each coloured as the operator it is, so the difference between a variable evaluated once and one evaluated every time it is read is visible in the file.
  </Feature>
  <Feature title="Variables and functions" icon="gear">
    `$(VAR)` and `${VAR}`, the automatic variables `$@`, `$<`, `$^`, `$?` and `$*`, the `$$` that escapes a dollar into the shell, and the built-in functions — `shell`, `wildcard`, `patsubst`, `foreach`, `call`, `if`, `info`, `error` and the rest — named inside their call.
  </Feature>
  <Feature title="Conditionals and recipes" icon="terminal">
    `ifeq`, `ifneq`, `ifdef`, `ifndef`, `else ifdef`, `endif`, and `define`/`endef` blocks. A recipe is its own scope, with the `@` and `-` prefixes and the backslash continuation coloured, and make's variables still resolved inside it.
  </Feature>
</Features>

## Notes

<Details summary="Why these names and not a pattern">

`Makefile`, `makefile` and `GNUmakefile` are the three names GNU Make looks for on its own, in that order, and `BSDmakefile` is the one BSD make prefers. Those four are not negotiable. `.mk` is what an included fragment is called by convention, and `.mak` and `.make` are the same fragment under two older spellings.

`Makefile.am` and `Makefile.in` are the automake input and the configure output. Both are Make syntax with extra conventions on top, so the grammar reads them correctly and the extra conventions simply go uncoloured. `Makefile.inc` is the shared fragment BSD ports keep. `Kbuild` is the Linux kernel's, and it is Make.

What is missing is the shape rather than the names. `Makefile.*` is a pattern, and a manifest holds names and suffixes, not globs: `Makefile.am` is claimed because it is spelled out, and `Makefile.local` is not claimed at all, because its last dotted segment is `local` and no list can hold every word a team puts after the dot.

</Details>

<Details summary="Why justfile is not claimed">

[just](https://github.com/casey/just) looks like Make from across the room and is a different language up close. It has one assignment operator rather than four. Its recipes are indented with spaces, and a tab is not special. It has `set` statements, `[attribute]` annotations, typed parameters with defaults, and `{{…}}` interpolation that Make would read as two nested variable references.

Colouring a `justfile` with the Make grammar would mark its interpolations as variables that are not there and miss every construct just added. It deserves its own extension with the `just` grammar, and this one leaves it alone.

</Details>

<Details summary="Recipes hold shell, and it is not coloured as shell">

A recipe line is handed to `/bin/sh`. The grammar knows the line is a recipe — it colours the tab, the `@` and `-` prefixes, the backslash continuation and every make variable inside it — but the shell in between stays one plain run of text. A `for` loop in a recipe gets no keyword colour and a quoted string in a recipe gets no string colour.

That is a limit of the grammar rather than of this extension. No maintained TextMate grammar for Make embeds shell inside recipes: not the one Visual Studio Code ships, not the one it was converted from. Editors that do colour recipe shell use a Sublime `.sublime-syntax` or a tree-sitter parser, neither of which Phantom reads.

</Details>
