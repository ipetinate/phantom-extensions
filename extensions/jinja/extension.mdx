Jinja2 support for the Phantom editor. The extension declares the language — `.j2`, `.jinja`, `.jinja2`, the `{# #}` comment markers — and ships the TextMate grammar the Jinja editor plugin maintains. There is no language server here. Highlighting is the whole contribution.

## Highlights

<Features>
  <Feature title="The three delimiters" icon="brush">
    `{% … %}` statements, `{{ … }}` expressions and `{# … #}` comments. Inside them Phantom colours the tag keywords, the operators, quoted strings with their escapes, `true`, `false` and `none`, and the punctuation. Variable, filter and test names are recognised and left in the foreground colour.
  </Feature>
  <Feature title="The host language is left alone" icon="check">
    The text around the tags keeps its own colour — none — whether the template writes HTML, YAML, Markdown or a shell script. See below for why that is a decision and not a gap.
  </Feature>
  <Feature title="No server to install" icon="package">
    Nothing runs. The grammar is data the editor reads, so the extension needs no binary on your `PATH` and asks for no permission.
  </Feature>
</Features>

## Getting started

<Steps>
  <Step title="Install the extension">
    In Phantom, open the Extensions pane in the sidebar (or Settings → Extensions) and press **Install** next to Jinja2.
  </Step>
  <Step title="Open a .j2 file">
    Colour appears at once. Phantom claims no file type of its own, so there is nothing to promote and no conflict to resolve.
  </Step>
</Steps>

## Why the host language is not coloured

<Details summary="The decision, and the measurement behind it">

A Jinja2 template is two languages at once: the Jinja2 tags, and whatever the template writes. The upstream plugin handles this by mapping the suffix to a host: bare `.j2` means HTML there, `.md.j2` means Markdown, `.yaml.j2` means YAML.

This extension does not follow that, for two reasons.

Bare `.j2` says nothing about the host, so mapping it to HTML is a guess. A compound suffix is a different matter, and it is expressible: a language's `extensions` list holds single suffixes, but `fileNamePatterns` takes globs, so `*.md.j2` and `*.{yml,yaml}.j2` are one manifest entry each. What is missing is a file that needs them. Of the 31 `.j2` files measured here, 30 carry no suffix before `.j2` at all, and the one that does is `pritunl.conf.j2`, whose `.conf` host has no grammar in this registry.

The measurement then said the host buys almost nothing. Over those 31 files, which are Markdown and prose templates, colour reached 10.0% of non-whitespace with Jinja2 alone, 10.1% with the HTML host and 13.9% with the Markdown host. Phantom's nine token kinds do not paint Markdown prose or HTML text, so a host grammar mostly adds scopes nothing draws — while a wrong guess would mis-colour a template whose host is a shell script or a JSON file.

So the plain Jinja2 grammar ships. It colours the tags and leaves the surrounding text alone.

</Details>

## Measured coverage

<Details summary="How much of a real template this colours">

Measured over the 31 `.j2` files in the owner's checkouts, 19,562 non-whitespace characters: **10.0%** land on a scope Phantom paints.

That figure counts the whole file, and 80% of these files is Markdown prose Jinja2 has no claim on. Of the 3,964 characters that are Jinja2 syntax, **49.3%** are painted.

</Details>

## Troubleshooting

<Details summary="A .md.j2 or .yaml.j2 file gets no Markdown or YAML colour">

It is recognised, as a `.j2` file: Phantom matches the last suffix, so the Jinja2 tags colour and the Markdown or YAML underneath stays plain text.

A future version could claim those names separately with `fileNamePatterns` and hand them a host grammar. Ask for it if you write such templates. It is left out today because no file in the repositories this extension was measured against has a suffix before `.j2`.

</Details>
